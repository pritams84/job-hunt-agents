## 1. What We Have Built

JobHunt AI is an end-to-end autonomous multi-agent job application SaaS platform designed to discover, match, tailor, and auto-submit job applications with human-like safety controls.

### Architectural Core Components
1. **Frontend Application (`src/`):**
   - React 18 + TypeScript + Vite + Tailwind CSS 3.4.
   - 11 complete views: Landing Page with interactive ATS simulator, Clerk Authentication (`SignIn`/`SignUp`), 4-Step Onboarding Wizard, Dashboard Command Center, Job Discovery Feed, Kanban & Table Applications Tracker, Candidate Profile Editor, Chronological Activity Log, Subscription & Billing Management, and Account Settings.
   - Custom design system: OLED dark mode (`#050505`), glassmorphism, Framer Motion transitions, GSAP tickers, and zero-layout-shift skeletons.
   - Realtime Supabase hooks (`useApplications`, `useQuota`, `useAgentStatus`).

2. **Autonomous Multi-Agent Engine (`src/lib/agents/`):**
   - **Agent 1 (Profile Parser):** Extracts structured candidate schema from resumes via NVIDIA Nemotron 70B with self-healing JSON repair.
   - **Agent 2 (Job Discovery):** Multi-platform ingestion (RemoteOK, Greenhouse, Lever) with SHA-256 deduplication.
   - **Agent 3 (3-Stage Matcher):** Hard deterministic filters -> Vector Cosine Similarity (pgvector 1536) -> LLM Qualitative Fit evaluation.
   - **Agent 4 (Tailor & Auditor):** Dual-agent adversarial loop generating custom cover letters and resume bullets with strict fact-checking against master profile.
   - **Agent 5 (Playwright Worker):** Semantic form auto-fill with human jitter delays (300ms–1200ms) and zero-bypass CAPTCHA safety.
   - **Agent 6 (Inbound Status Tracker):** Webhook classifier for recruiter email updates and interview invitations.
   - **Agent 7 (Orchestrator & Quota Governor):** Master pipeline coordinator enforcing tier caps with Emergency Killswitch.

3. **Backend API & Webhooks (`server/index.ts`):**
   - Express server handling Clerk Svix webhooks (`user.created`, `user.updated`, `user.deleted`).
   - Stripe Webhooks (`checkout.session.completed`, `customer.subscription.updated`, `invoice.payment_succeeded`).
   - Stripe Billing Checkout & Customer Portal session endpoints.

4. **Database & Migrations (`supabase/` & `scripts/`):**
   - Live PostgreSQL schema on Supabase with 7 core tables, Row-Level Security (RLS), pgvector extension, and HNSW indexes.

## 2. Issues & Findings Ranked by Severity

### 🚨 Blockers (Must Fix)

#### 1. Clerk User ID vs. Supabase User UUID Foreign Key Mismatch
- **Location:** `src/hooks/useQuota.ts:23`, `src/hooks/useApplications.ts:52`, `src/pages/DashboardPage.tsx:24`
- **Issue:** In the frontend, `user?.id` from `@clerk/clerk-react` returns a Clerk string format (e.g. `user_2...`). However, the Supabase schema defines `user_id` across `subscriptions`, `applications`, and `profiles` as a PostgreSQL `UUID REFERENCES public.users(id)`.
- **Impact:** Direct queries filter on `user_id = 'user_2...'`, resulting in PostgreSQL type mismatch errors (`invalid input syntax for type uuid`) or empty result sets.
- **Recommended Fix:** 
  - Add a lightweight `useCurrentProfile()` hook that maps `clerk_id` to `public.users.id`, or update RPC functions to accept Clerk ID directly.

#### 2. Playwright Worker placed in Client-Side Source Tree
- **Location:** `src/lib/workers/playwright.ts`
- **Issue:** `playwright` is a Node.js runtime browser automation engine. Having it in `src/` risks being bundled by Vite during production client builds.
- **Impact:** Vite build warnings or browser bundle corruption if imported in frontend components.
- **Recommended Fix:** Move all Playwright browser execution code to `server/workers/` or background worker scripts.

---

### ⚠️ Major Findings

#### 3. Frontend Pages Relying on Static Mock Data
- **Location:** `src/pages/JobsPage.tsx:5-12`, `src/pages/BillingPage.tsx:8-15`
- **Issue:** `JobsPage` uses a static `const jobs = [...]` array instead of querying `public.job_listings` via Supabase. `BillingPage` has static usage numbers and does not trigger `POST /api/billing/create-checkout`.
- **Recommended Fix:** Connect `JobsPage.tsx` to `public.job_listings` using TanStack Query and wire the upgrade buttons in `BillingPage.tsx` to the backend Stripe Checkout API.

#### 4. Stripe Webhook Signature Bypass in Development Mode
- **Location:** `server/index.ts:51-59`
- **Issue:** If `STRIPE_WEBHOOK_SECRET` is unset, the endpoint falls back to parsing unverified JSON payloads.
- **Impact:** Potential security vulnerability if deployed to production without environment variable validation.
- **Recommended Fix:** Enforce `process.env.NODE_ENV !== 'production'` check before allowing signature fallback.

### 💡 Minor / Nits

1. **Root tsconfig.json Scope:** `tsconfig.json` only includes `"src"`. Running `tsc` does not typecheck `server/index.ts` or `scripts/`. Consider adding a `tsconfig.server.json` or expanding the root tsconfig.
2. **Vitest Unit Test Runner:** Set up `vitest` in `package.json` to enable automated unit testing alongside `scripts/test-pipeline.ts`.
